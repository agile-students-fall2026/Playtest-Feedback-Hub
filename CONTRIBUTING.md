# Contributing to Playtest Feedback Hub

## 1. Project Overview

Playtest Feedback Hub is a mobile web application that helps game developers, game designers, and software developers collect, organize, and review feedback from playtesters and application testers.

We welcome contributions that improve the usability, reliability, and functionality of the application.

## 2. Team Norms

All contributors are expected to follow our agreed-upon team norms.

- Communicate respectfully and constructively.
- Participate in team meetings and project discussions.
- Complete assigned tasks and communicate delays early.
- Ask for help when blocked.
- Provide constructive feedback during code reviews.
- Make important decisions collaboratively.

The team will follow the agreed-upon norms documented in our course's Team Norms guidelines.

## 3. Git Workflow

We use Git and GitHub for version control and collaboration.

1. Pull the latest changes from main before starting new work.
1. Create a separate branch for each feature or bug fix.
1. Make small, focused commits with descriptive messages.
1. Push your branch to GitHub.
1. Open a Pull Request targeting the master branch.
1. Describe the changes and any testing performed.
1. Request a review from another team member.
1. Address review feedback before merging.

Do not commit directly to main unless the team explicitly agrees otherwise.

## 4. Contribution Guidelines

Before contributing:

- Check existing issues and Pull Requests to avoid duplicating work.
- Discuss significant new features or changes with the team.
- Keep changes focused and relevant to the project.
- Follow the project's established coding and naming conventions.
- Test your changes before submitting a Pull Request.
- Never commit passwords, API keys, or other sensitive information.

## 5. Local Development Setup

Development setup instructions will be finalized once the project's technology stack and repository structure are established.

Contributors will need to:

1. Install Git and the project's required development tools.
1. Clone the repository.
1. Install the project's dependencies.
1. Configure any required environment variables.
1. Start the application locally.

Exact commands and configuration details will be added when the development environment is established.

## 6. Building and Testing

Build and test instructions will be added once the project's build system and testing framework are established.

Contributors should run the available checks and tests before submitting a Pull Request and report any known failures.

## 7. Pull Request Expectations

Every Pull Request should:

- have a clear, descriptive title.
- explain what changed and why.
- reference a related issue or task when applicable.
- include relevant test results.
- be reviewed and approved according to the team's agreed-upon process.

Thank you for helping improve Playtest Feedback Hub!
